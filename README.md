# 健身房 · 器械与团课

健身房的日常台账：**训练区**、**器械**、**团课**、**会员**、**更衣柜**、**体验入场**。

业务重点：
- **团课名额是硬的**：已报名不能超过名额，页面上的「加一位」满了会被后端拦住；
- 训练区停用前要求先把器械挪走；器械只能放进「开放」的训练区；
- 会员卡到期没到期由后端算好（`expired` 字段）连同数据一起给前端；
- **体验入场单一动作落单**：称呼、开放训练区、空闲更衣柜一次写清，训练区容纳和
  更衣柜占用在同一个事务里校验，不分两步走；
- **在馆人头是硬的**：在馆体验客 + 同一训练区、上课时段罩住此刻的团课已报名，
  加起来不能超过训练区容纳上限，超了开不出单；
- 柜子被没离场的单子占着时别人拿不走（数据库唯一键兜底）；钥匙没交回不能离场，
  先补记钥匙归还再离场；
- 开单只登记入场：不把体验客转成会员，介绍会员（停卡、过期都行）只写在单上作备注，
  不动他的卡状态；训练区停用不清在馆单，在馆单只能走离场收口。

## 技术栈

- 后端：Spring Boot 3.3 / Java 17、**JdbcTemplate + Map**（SQL 里用别名直接取成前端要的字段名，
  不建实体类、不写 RowMapper）、MySQL 8、Redis 7
- 前端：Vue 3（Composition API + **不用 axios，直接 fetch**）+ Element Plus + Vite
- 一键起：`./start.sh`

## 业务模块

1. **训练区**（`gym_area`）—— 编号名称、面积与容纳人数、开放与停用
2. **器械**（`gym_machine`）—— 编号名称类型、归属训练区、可用/占用/维修
3. **团课**（`gym_class`）—— 编号名称教练、日期时间与上下课时间、上课训练区、名额与已报名、待开课/已约满/已完成
4. **会员**（`gym_member`）—— 编号姓名电话、卡种、到期日、正常与已停卡
5. **更衣柜**（`gym_locker`）—— 编号位置、正常/故障；空闲与否由未离场的入场单推导
6. **体验入场**（`gym_visit`）—— 单号称呼、训练区、更衣柜、介绍会员备注、钥匙归还、在馆/已离场
