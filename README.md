# 健身房 · 器械与团课

健身房的日常台账：**训练区**、**器械**、**团课**、**会员**。

业务重点：
- **团课名额是硬的**：已报名不能超过名额，页面上的「加一位」满了会被后端拦住；
- 训练区停用前要求先把器械挪走；器械只能放进「开放」的训练区；
- 会员卡到期没到期由后端算好（`expired` 字段）连同数据一起给前端；
- **体验入场单一事一办**：开单在同一个事务里查训练区容纳、占更衣柜、落单，
  拆开做第二天柜门钥匙和在馆人头就对不上；
- 在馆人头 = 该区「在馆」体验客 + 同区同时段团课的已报名数，不能超过训练区容纳上限；
- 钥匙没还，离场不成立，柜子继续占、人头继续算。

## 技术栈

- 后端：Spring Boot 3.3 / Java 17、**JdbcTemplate + Map**（SQL 里用别名直接取成前端要的字段名，
  不建实体类、不写 RowMapper）、MySQL 8、Redis 7
- 前端：Vue 3（Composition API + **不用 axios，直接 fetch**）+ Element Plus + Vite
- 一键起：`./start.sh`

## 业务模块

1. **训练区**（`gym_area`）—— 编号名称、面积与容纳人数、开放与停用
2. **器械**（`gym_machine`）—— 编号名称类型、归属训练区、可用/占用/维修
3. **团课**（`gym_class`）—— 编号名称教练、日期时间、挂在哪个训练区、名额与已报名、待开课/已约满/已完成
4. **会员**（`gym_member`）—— 编号姓名电话、卡种、到期日、正常与已停卡
5. **更衣柜**（`gym_locker`）—— 编号、空闲/故障；「占用」不另存，由未离场的入场单推出来
6. **体验入场单**（`gym_trial_ticket`）—— 体验客称呼、训练区、更衣柜、入场日期与时段、
   介绍人备注、在馆/已离场、钥匙归还

体验入场单的规矩（按场务这条走）：
- 开单必须同时选上**开放的训练区**和**空闲的更衣柜**，缺一样单子落不下去；
- 介绍人只是单子上的备注：已停卡、卡过期的会员也能当介绍人；开单不把体验客转成会员，
  也不动介绍人的卡状态；
- 训练区被停用时，已在馆的单子不清、不改，只能走离场收口；新单子选不到停用区；
- 离场前先补记钥匙归还，否则离场被拦住。
